// Anatomy of a skill

One Markdown file, read by every harness

SKILL.md reference.md templates/
--- name: terraform-style description: Terraform/HCL style conventions for writing readable, reusable modules — … Use when writing, reviewing, or refactoring Terraform code … license: MIT --- # Terraform style conventions Apply these conventions to every module and root configuration … For the rationale behind each rule, see reference.md. ## 1. Collections: set(string) for unordered, unique items
  1. 1

    The description is the trigger

    Harnesses read only name and description to decide when to load a skill, so every description is written for recall, with explicit “Use when …” phrases — and Tier 1 evals hold it to that.

  2. 2

    Progressive disclosure

    A compact SKILL.md body, well inside Codex's ~8 KB budget. Rationale, extended examples and templates live in companion files the agent opens only when it needs them.

  3. 3

    Written once, linked everywhere

    Each skill exists exactly once under plugins/<plugin>/skills/. The Claude Code and Codex marketplaces and install.sh all point at the same tree — no copies to drift.

// Evaluated, not vibes

Every skill is measured before it ships

evolve runs three tiers against every skill, on every model we support. Results and token cost are committed alongside the code.

Tier 0

Static checks

Frontmatter, manifests, version sync and eval-suite schemas — evolve run checks --strict on every push.

Tier 1

Trigger accuracy

Real headless agent sessions: does the skill load for the right prompts — and stay quiet for near-miss negatives?

Tier 2

Behavioral evals

Does following the skill produce correct work? Graded deterministically — terraform validate, tflint, file and regex checks — against a no-skill baseline.
