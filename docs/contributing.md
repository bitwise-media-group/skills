# Contributing

The full conventions live in [`AGENTS.md`](https://github.com/bitwise-media-group/skills/blob/main/AGENTS.md), which
coding agents read automatically. This page is the condensed version.

## Layout

```text
plugins/<plugin>/
  .claude-plugin/plugin.json      # Claude Code manifest
  .codex-plugin/plugin.json       # Codex CLI manifest (same version)
  skills/<skill-name>/
    SKILL.md                      # the skill — the single source of truth
    reference.md, templates/      # optional companions (progressive disclosure)
  evals/<skill-name>/
    triggers.json, evals.json     # the eval suite (kept out of the installed skill)
    results.json                  # raw results, rewritten by the sweeps
  commands/*.md                   # optional Claude Code slash commands
  EVALUATION.md                   # per-eval report (generated by evolve)
```

- Each skill exists **exactly once**. The Claude and Codex marketplaces and `install.sh` all point at this tree.
- The skill directory name equals the frontmatter `name`.
- Skill names are namespaced by plugin prefix (`terraform-style`, not `style`) because Codex, Antigravity, and OpenCode
  install skills into flat, shared directories.

## Dual manifests

| Consumer    | Marketplace (repo root)            | Plugin manifest                          |
| ----------- | ---------------------------------- | ---------------------------------------- |
| Claude Code | `.claude-plugin/marketplace.json`  | `plugins/<n>/.claude-plugin/plugin.json` |
| Codex CLI   | `.agents/plugins/marketplace.json` | `plugins/<n>/.codex-plugin/plugin.json`  |

- Versions stay in sync between the two plugin manifests (strict semver — Codex requires it); `make lint` enforces it.
- Marketplace `source` paths are explicit and `./`-prefixed (`"./plugins/terraform"`).
- Never add a `hooks/` directory to a plugin: Codex discovers `hooks/hooks.json` with an incompatible schema.

## Skill frontmatter

Portable fields only — `name` and `description` are the only fields every harness reads:

- `name`: lowercase kebab-case, ≤ 64 characters, equal to the directory name.
- `description`: third person, ≤ 1024 characters, on one line, with explicit trigger phrases ("Use when …"). It is the
  only signal harnesses use to decide activation, so write it for recall.
- `license`: `MIT`.

No Claude-specific fields (`allowed-tools`, `model`, `context`, `hooks`, …) unless a skill genuinely needs them.

## Progressive disclosure

Keep `SKILL.md` compact — well under 500 lines, since Codex truncates bodies around 8 KB. Put rationale, extended
examples, and edge cases in companion files (`reference.md`, `templates/`) linked by relative path. Refer to sibling
skills by **name** ("see the `terraform-style` skill"), never by path: installed layouts differ per tool.

## Evals

Every skill ships an [evolve](https://oss.bitwisemedia.uk/evolve/) suite under `plugins/<plugin>/evals/<skill>/`:

- `triggers.json` — 10–20 `{query, should_trigger}` cases; the negatives must be near-misses.
- `evals.json` — 2–5 behavioral evals with assertions, deterministic first (`terraform validate`, `tflint`, file and
  regex checks) and LLM-judged only where nothing else fits.
- Eval `files` are fixture paths, never inline content.

Changing a `description` means rerunning Tier 1 (`make triggers`). Results and token cost are committed, and
`make report` regenerates the [evaluation reports](evaluation.md) from them — never edit those by hand.

## Docs site

This site is [Zensical](https://zensical.org) with the org's terracotta theme (`overrides/`,
`docs/stylesheets/extra.css`). The landing, install, and contributing pages are hand-written; everything under
`docs/plugins/`, plus `docs/evaluation.md` and the landing's plugin grid and stat row, is **generated** by
`scripts/gen-docs.py` from `SKILL.md`, the manifests, and the evolve reports.

```sh
make docs-gen    # regenerate the generated pages (make report runs it too)
make docs        # regenerate, then build the site into site/
make serve       # live preview at http://localhost:8002/skills/
```

A new skill or plugin needs a matching entry in the `nav` of `zensical.toml`; `make lint` fails until it has one (the
generator prints the expected section) or while any generated page is stale.

## Validation

```sh
make fmt     # prettier + SPDX license headers
make lint    # markdownlint, evolve Tier 0 checks, eval JSON, plugin validate, generated-docs check
make pr      # fmt, lint, test — the full local gate
```

Commits follow [Conventional Commits](https://www.conventionalcommits.org/); release-please derives each plugin's
version and changelog from them.
